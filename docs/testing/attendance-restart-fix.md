# 退勤の途中保存・再起動時の重複修正（2026-10-20）

基線: `320baa3d12576045a3864dbd7b2870f89c90307c`。
環境証拠 v0.1.0 の不合格を扱う限定修正。製品全体の採用・公開・本番受入ではない。

## 原因と修正

旧処理は勤怠追加と入場解除を別々に保存し、画面内の `sessionSaved` だけで再送を防いでいた。
1回目だけ成功した後に再起動すると、このフラグが失われ同じ入場の勤怠が追加された。

- `completeSession` で勤怠追加と `current_session = null` を同一キーの1回の保存にする。
- 旧版の途中保存は現場ID・入場時刻の両方が一致する勤怠が1件なら、その記録をそのまま保持して入場解除だけ保存する。
- 完了済みの同じ退勤は追加も書込みもしない。作業画面が保持する入場時刻を渡し、別の入場記録がある場合は停止する。
- 同じ入場の勤怠が既に複数ある場合は、自動削除・統合せず保存を止める。既存の請求snapshotを再計算しない。
- root/web の `work.js` は同一。旧UIの `saveSession` と保存形式、認証、同期、本番設定は変更しない。

## 証拠の区分

- **既存実装**: 上記基線のコード。ui-v2や10/10 Drive版を新たに採用したものではない。
- **既存試験記録**: `storage-read-guard.md` は10/9時点の40/61件。二段保存後の再起動は対象外と記載されている。
- **環境証拠 v0.1.0**: 10/20の追加試験で途中保存→再起動→退勤が1件から2件となった。旧証拠は固定して保持する。
- **今回の検証**: Senlingsの架空データだけで保存層62件、ブラウザー61件、再起動7件。保存層は旧40件＋退勤保護2件＋新規20件。ブラウザー61件中の旧二段保存2件を新しい1回保存の失敗条件に更新した。詳細結果と時刻は別添ログ参照。
- **本人実機確認**: 未実施。澪の試験結果は含まない。

## 再起動試験7件

1. v0.1.0の途中保存JSONそのもの→ブラウザー起動→退勤→完全終了・再起動→JSON読戻し。勤怠1件のまま、入場解除以外は等価。
2. 連絡先・別現場・別勤怠・経費・写真メタデータ・既存請求・イベント・未知項目を加えた途中保存→解除書込み失敗→再起動→再操作。元の勤怠・他データを保持。
3. 現場追加→改行付き原文→出勤→再起動→退勤→月次請求下書き→再起動→JSON出力。退勤は1回保存、同操作の再発火も追加なし。新勤怠1件・新請求1件・請求内勤怠1件。
4. 正常な入場から退勤書込み失敗→再起動→再操作。失敗時は元バイト不変、再操作後は追加1件。
5. 書込み直前の読取失敗→再起動→再操作。失敗時は元バイト不変、再操作後は追加1件。
6. 既に重複した架空記録→再起動を挟んで再操作。成功を表示せず元バイトを保持。
7. 古い退勤画面のまま入場記録を差し替えた場合、別の入場を解除せず停止。

## 再実行

Node、既存Playwright、実行可能なChromiumを使う。依存追加なし。
`CHROMIUM_PATH` と `PLAYWRIGHT_MODULE` を環境の実体へ設定する。
`SENLINGS_EVIDENCE` にログ出力先を設定する。

```sh
node tests/check.mjs
TZ=Asia/Tokyo node tests/browser.cjs
TZ=Asia/Tokyo node tests/attendance-restart.cjs
```

サーバーとブラウザーは同じ試験プロセスから起動する。localhostの一時ポート、新規の専用profileだけを使う。
外部リクエスト・Service Workerを遮断。旧UIのFirebaseは既存試験のstub。
再起動試験は毎回新しい一時profileを作成し、ケース内では同じorigin/profileで完全終了・再起動する。
完了後に試験用profileとサーバーを終了する。本人のブラウザーや実データには接続しない。

## 残件・限界

- 既に重複した履歴とそこから作られた請求の照合・訂正は別途。自動削除しない。
- 複数タブの同時書込みの排他は未対応。今回の別入場照合は同時書込み全体の解決ではない。
- ブラウザーを通常終了して再起動した試験。OS強制終了・電源断・ディスク故障の耐久性は未確認。
- 本人端末、保存済みmain環境、実認証/Firestore/本番Rules、外部CDNを使うExcel正常出力は未確認。
- 既存の請求カードは再表示時にリセットされるため、請求保持の判定はJSON出力。保存済み請求一覧機能の追加ではない。
- Pull/地図の後続原物と6/6ログ、10/10 Drive保存版との系統対応は未解決。
- ui-v2の全機能受入は未完了。新しい公開・本番反映・共有権限変更は行わない。

採否前はこの候補を隔離環境だけで使う。戻す場合も検証profileを分け、途中保存が残るデータへ旧コードを適用しない。
