2026-10-23。既存 `fix/attendance-restart-20261020` の続き。
原本320baa3d、勤怠修正f544242dを祖先として保持する。既存UIを拡張し、別アプリは作らない。

## 今回の実装範囲

- 物件情報を受け取る → 内容と版を確認 → 本人が現場へ追加／新しい版を反映。
- 現場の申し送りから、渡したい項目を選択 → 表示内容を確認 → JSONファイルを作る。
- LINE等の文章は既存「現場を追加する」の原文欄へ。住所・担当者・電話も任意で保存できる。
- 写真は長辺1280pxまでの縮小JPEG＋メタ情報を既存photosへ保存。元画像は保存しない。
  1枚のDataURL上限700,000文字、全縮小画像合計3,000,000文字。実際の保存容量不足も保存エラーとして止める。
- 私的メモ、SOS、帰還時の本人記録を保存し、仕舞いから見返す。個別のテキスト／縮小写真を持ち出せる。
- SOSは端末内保存と連絡文の準備まで。コピー、テキスト出力、明示的な電話操作を用意。
  自動送信せず、コピーや電話の起動を到達扱いにしない。架空の電話番号では発信試験しない。
- 仕舞い経由の帰還で入場時刻が渡っていなかった経路も修正。
  旧版の途中保存に今回のメモがある場合、元勤怠を変えず別の私的記録として同じ保存に含める。
- 既存の工事別CSVを新UIに接続。請求・口座設定画面を接続し、設定全体を一度で保存。
  従来キーは残し、未移行値は読み取る。設定保存後は全データJSONにも含まれる。

## 渡す形式と所有

`senlings.project-handoff`, `schema_version: 1`。
`source_project_id`, 正整数の`revision`, `project.name` と本人が選んだ物件項目のみ。
受取側のローカル現場IDは別に生成。送信元IDと版は照合用の申告で、本人確認や案件の受任の証明ではない。

- 同じID・版・内容：受取済み。現場も原本も増やさない。
- 同じID・版で内容が違う：変更せず停止し、版の確認を求める。
- 新しい版：本人がプレビューして反映。含まれた項目のみ更新し、過去の受取原本・未指定項目・本人記録を保持。
- 受け取っていない古い版：上書きを拒否。受取済みの古い版の再読取は受取済み扱い。
- 未対応の形式・項目：黙って採用しない。

受取時の文字列原本と正規化した内容をhandoff_receiptsへ保存。受取と現場更新は同じ保存。
私的メモ・写真・勤怠・請求・口座・受取履歴は物件の選択書き出しに含めない。
元の連絡原文は初期選択を外し、選択したときだけ渡す。

接続先を澪に固定しない。本人がファイルの渡し先を選べる。
API接続・共有DB・認証・相手の受任ACK・到達確認は今回成立させていない。
この形式は今回の手渡し用実装。双方合意済みの共通仕様と扱わない。

## 最初に通す操作

1. 隔離した新規ブラウザプロファイルで `web/index.html` をローカルHTTPから開く。
2. 架空の物件JSONを受け取り、現場名・住所・担当者・原文を確認して追加する。
3. 同じJSONを再度受け取り、現場が増えないことを確認する。
4. 現場へ入場し、メモ・縮小写真・SOSをそれぞれ端末内に保存する。
5. ブラウザを完全に終了して開き直し、「続きから入る」。入場時刻と記録を確認する。
6. 仕舞いタブの帰還からメモ付きで退勤する。再起動後も勤怠が1件であることを確認する。
7. 仕舞いで記録を開き、1件だけ書き出す。物件書き出しに私的記録が混じらないことを確認する。
8. 全データJSONをダウンロードし、元の別現場・請求・未知フィールドが保たれることを比較する。

## 再実行

Node.js 24.19.0。ビルド工程なし。既存Webルートに対しローカルHTTPを使用する。
通常の手動確認は `python3 -m http.server 4173 --bind 127.0.0.1 --directory web`。
終了はCtrl+C。実データ・本番オリジン・既存プロファイルを流用しない。

各ブラウザ試験は自身のローカルHTTPサーバーと架空データのプロファイルを使い、外部通信とService Workerを遮断。
旧UIのFirebaseは既存試験用スタブ。新認証・実DB・メール・実電話を使わない。
実行環境がコマンドごとにネットワークを分離する場合も、サーバーとブラウザを同じ試験プロセス内で起動する。
フォントは任意のFONTCONFIG_FILEで指定可能。描画確認用スクリーンショットは内部検品のみ。
